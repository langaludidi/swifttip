# SwiftTip — True State

> One page, as of 2026-07-19. Replaces the "what's actually real" question with a map.
> Detail and evidence for everything here lives in `06-production-checklist.md`,
> `08-funds-model-decision.md`, and the dated reports in this folder — this page is
> the index, not a replacement for them.

## Built + tested (proven live, now regression-locked)

- **Customer tip flow core**: scan → worker profile → amount → Paystack Checkout
  redirect → settlement *only* via HMAC-verified webhook, never a browser redirect.
- **Worker onboarding**: signup, KYC document upload (private bucket, signed
  URLs only), submission (server-enforced ≥1 document).
- **Admin KYC review**: `decide_kyc()` — atomic, audited, the sole path that can
  set `active=true`. Full admin console screen (`KycReviewScreen`) wired to live data.
- **Admin MFA (H2)**: `aal2` required on `review-kyc`/`set-payout-status` (the
  layer that matters — both bypass RLS via the service role) *and* on
  `auth_role()`'s `'admin'` return value (the remaining direct-table-read paths).
  Workers unaffected at `aal1`. Enrollment UI + login challenge screen built.
- **C1–C6, three drift incidents (`settle_tip`, `kyc` bucket, stale `decide_kyc`
  overload)**: all found live-exploited-or-provably-exploitable, all fixed, all
  verified in both directions.
- **`create-tip` amount bounds**: R5–R1000, server-side, integer cents.
- **Automated regression suite** (`npm run test:regression`, `tests/regression/`,
  13 tests, all passing against live infra as of today): webhook signature
  rejects unsigned/wrong-sig; admin `aal2` gate denies `aal1` and allows `aal2`
  on both MFA-gated functions; amount bounds reject below-R5/above-R1000/zero;
  a fresh worker defaults `active=false`; the C5 and C6 exploit chains both
  still fail exactly as they did when fixed; a worker's own non-privileged
  profile edits still work. Needs `SUPABASE_SERVICE_ROLE_KEY` locally (test-only,
  documented in `.env.example`, never committed).

## Open (known, not yet fixed — ranked)

1. **Declined card never resolves to a failure state.** Confirmed (multi-source):
   Paystack sends no webhook for a failed one-time charge at all. Fix designed
   (Verify Transaction API, called from `get-tip-status`), not built. **Highest
   priority — this is the actual Tier 1 north star test.**
2. **Vercel production deployment** — stale branch (`claude/nice-bardeen-we0hfg`,
   missing every fix above) + wrong `VITE_SUPABASE_URL` (points at the dashboard
   page, not the API). Exact fix values given; in progress on your side.
3. **Admin-side integrity gap** — an `aal2` admin session can still bypass
   `decide_kyc()` via a direct `workers` UPDATE (no audit trail, no validation).
   Narrowed by H2 (now needs `aal2` too) but not closed. Needs trigger-level
   enforcement.
4. `request-payout` has no KYC-status gate (balance-only check).
5. Real mobile OTP still hardcoded (`4321`); `send-sms` exists, unused.
6. `useEmployerData` — two independent bugs (wrong id resolution + two
   nonexistent columns) — employer dashboard silently shows "no workers"
   regardless of reality.
7. Login brute-force protection — no account-level lockout exists (native hook
   needs a plan upgrade); CAPTCHA available but off; no fix chosen.
8. Password floor is `6` at the Supabase project level, not the `8` the app's
   own UI claims — one-line config fix identified, not applied.
9. Signup-while-logged-in bug — root-caused with a proposed fix and repro
   steps, not live-confirmed (needs a DB write, was out of scope when found)
   or fixed yet.
10. Admin console: transactions view, payout-queue wiring, worker-management
    wiring still render mock data (`AdminFlow.jsx`).
11. Pre-pilot gate open items: `create-tip`/signup rate limiting unverified,
    DB backup restore untested, no error monitoring, password reset untested
    end-to-end.
12. ~~C7 (anon reads on `qr_codes`/`workers` with no RLS)~~ — **checked and
    closed as a non-issue**: `qr_codes` doesn't exist in this schema, and
    `workers`'s public-read policy is already correctly row-scoped. This was
    the phantom workspace's concern, not this repo's.

## Frozen (blocked on a decision outside engineering)

- **The entire payout/wallet architecture** — pass-through vs. custody vs.
  hybrid, pending the SA fintech/regulatory specialist review
  (`08-funds-model-decision.md`). No payout UI work happens until this resolves.
- **Employer self-service, admin onboarding** — deferred to pilot #2 by design.
  One prerequisite already flagged: `workers` INSERT doesn't constrain
  `employer_id` — must be fixed *before* either ships, not after.

## Deferred (explicitly out of scope for pilot #1, by design)

NFC tipping, customer accounts, loyalty/rewards, referrals, advanced analytics,
payroll integration, multi-country/currency, native apps, gamification, worker
lifecycle/suspension states beyond today's KYC approve/reject (no such decision
has actually been made in this repo — a session-sync claim that it had was
false, see `CLAUDE.md`'s note on the phantom workspace), venue-level worker
discovery (pilot #2 candidate, needs POPIA review first).
